# 音声をサーバーで中継し、面接ごとのDOで状態を管理する

個人用の面接練習に加えて、本番運用を想定した接続・記録・利用制限の設計を成果物として説明したいため、ブラウザとGemini Liveの間にCloudflare側の音声中継を置きます。再接続や別タブからの引き継ぎでも同じ面接の状態と送信権を管理するため、面接ごとにDurable Objectを割り当てます。単純な中継より増える費用と障害処理を引き受け、サーバー側で制御する責務を明確にします。

## 検討した選択肢

- ブラウザ直結：短命トークンにより長期キーを隠し、中継の遅延と実装負担を減らせます。本番で成立しない方式だから除外したのではなく、今回のサーバー側制御と学習目的から中継を選びました。
- 通常Workerだけの中継：通信は実現できますが、再接続先が変わる場合の状態・所有権・競合管理が別途必要です。
- 面接ごとのDO：面接IDによる状態と接続の管理をまとめられるため採用しました。

## 影響

外向きWebSocketの保持中はDOの休止による節約を前提にしません。DOも通信やメモリを永続的に維持するわけではないため、再開情報と未保存テキストの復旧設計が必要です。Google側の再開に伴う一時保持と、アプリ側の音声非保存は区別します。

現在の動作は[MVP仕様書](../spec/mvp.md)、根拠と未検証事項は[技術調査](../research/platform-integration.md)を参照してください。
