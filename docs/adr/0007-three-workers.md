# Web・面接DO・評価Consumerを3 Workersへ分ける

2026年11月2日合意。Web、面接DOを公開するInterview、評価QueueとDLQを受信するEvaluationを独立したWorkerにします。画面・API、長時間の音声接続、非同期評価の変更と配置を分け、各責務の設定と秘密値を分離できる構成を選びます。個人用MVPの価値に加え、転職活動で判断理由と運用負担を説明できる成果物にする目的があります。Worker数の多さ自体を品質の根拠にはしません。

## 検討した選択肢

- 1 Worker：起動・配置を単純にでき、Queueによる実行経路の分離も可能です。ただし各責務を独立して配置できません。
- WebとDO／評価の2 Workers：評価は独立しますが、Web更新と音声処理の配置が結び付きます。
- 3 Workers：Web、音声接続、評価を独立して変更できるため採用します。複数Worker起動、バインディング、契約互換性、配置順序の管理を引き受けます。

## 影響

[ADR 0004](0004-tanstack-start-with-void.md)のWebエントリ内にDOを公開する配置を変更します。StartとVoidの採用、[面接DO](0001-server-relayed-interviews.md)と[非同期評価](0002-queued-evaluation.md)の責務は維持します。共有D1や外部APIの障害まで隔離できるわけではなく、同時実行・重複防止は別途実装します。

アプリと共有契約を分離し、既存サンプルは回帰テストを含めて移行検証した後に削除します。3 Workersの接続が成立しない場合や、配置の独立性より運用負担が大きくなった場合は見直します。具体的な配置・合否条件・未検証範囲は[MVP仕様書](../spec/mvp.md#配置と業務モデル)を正とします。
