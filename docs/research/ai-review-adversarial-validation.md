# AIレビューの敵対的検証

2026年10月26日、PR #30の繰り返す未完了を受け、担当範囲の修正と未コミットの診断追加を対象に検証した。実モデルAPI・GitHubの再実行は行わず、SDKのHTTP応答を模擬して実処理へ入力した。

## 検証結果

| ---------------------------------------------------- | ---------------------------------------------------------------------- |
| 乱数seed固定の1000通りの重複・欠落・担当外・非文字列 | 件数整合、任意文字列の非保存、描画を確認                               |
| IDが存在しないのに重複件数だけがある偽造診断         | 受入れを再現し、拒否するよう修正                                       |
| 同じ期待IDを69回返す応答                             | Schemaの列挙・件数条件を満たすが、受信後に欠落68件・重複68件として拒否 |

| 補助資料の欠落・改変・容量超過                       | 拒否・再分割・単一対象での停止を既存回帰テストで確認                   |
| 履歴30件、各根拠が日本語500文字                      | 内部検証は成功するが約50KBとなり、SDK境界でOUTPUT_LIMITを再現          |

## 発見した問題と修正

Schemaの件数と列挙は一意性を保証しない。実行後検証は重複を拒否するため誤った完了にはならないが、AIが重複を生成すればCIは停止する。今回の診断で内訳を確認できる。再発そのものを排除するには応答形式と対応するSchemaの設計変更を検討する必要がある。

履歴作業の分割は入力容量が中心で、長い正常な出力が30KB制限を超える。これは今回の診断追加で導入した問題ではなく、この検証時点では未解決だった。短い根拠だけの従来テストでは発見できなかった。単に上限を引き上げず、応答件数・根拠長・共通項目・出力トークン予算を合わせた分割設計が必要である。再現テストは現状の停止を期待するもので、解決済みを意味しない。

検査成功は実モデルの成功保証ではない。モデルの資料不足申告、出力トークン不足、API障害、予算・時間超過による未完了は残る。これらを成功へ補正せず、検証済みの診断で区別する。

## 修正後の確認

確認済み一覧を必須キーのオブジェクトに変更し、重複する配列で件数だけ満たす回答を表現できなくした。余分なキー・欠落・false・旧配列形式は受信後も拒否する。

履歴作業は応答JSON最大サイズで分割するよう変更した。30件の日本語500文字根拠を用いた再現テストは、失敗を期待するものから、全担当IDが分割先に残り、各応答がSDK境界まで成功するテストへ置き換えた。上記の失敗結果は修正前の記録である。実モデルAPIでの再実行は未実施。

構造化出力の必須キー・追加プロパティ禁止は[公式仕様](https://developers.openai.com/api/docs/guides/structured-outputs)に従う。
