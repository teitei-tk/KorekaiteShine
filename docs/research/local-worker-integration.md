# 既存試作の移行とローカルWorker接続の検証記録

Web・Interview DO・Evaluationをローカルで接続する検証の記録です。Cloudflareへの配置、本番Access、実AI、クラウドD1の成功を示すものではありません。再実行は[ローカル開発手順](../runbooks/local-development.md)、要件は[MVP仕様書](../spec/mvp.md)を参照してください。

## 固定版と実行条件

2026年11月3日の接続検査では、Node.js 26.12.1、pnpm 12.15.0、Void 1.4.0、Cloudflare Viteプラグイン1.64.0、Wrangler 4.155.0、Miniflare 5.20261023.2-beta、Vite 8.3.5を使用しました。依存の原本は[共有ロックファイル](../../pnpm-lock.yaml)です。各統合検査の`results.json`にも実際に読み取った版とロックファイルのSHA256を保存します。

「ローカルD1」は、MiniflareのD1バインディングとSQLite保存先を指します。Cloudflareトークンや1Passwordの秘密値は使用していません。開発DBの保持確認だけはNode SQLiteの読み取り専用接続を使い、アプリのD1接続検査と区別します。

## 移行元の履歴と互換性

2026年10月30日、旧`apps/typespec-spike`で、TypeSpecからOpenAPI・API型・Ajv検証コードを生成し、React・TanStack Start・Voidを接続しました。開発サーバーとビルド済みWorkerの実HTTP通信、一覧2件と再取得をブラウザで確認しました。初回検証はVoid 1.3.0です。TypeSpec 1.17.0、React 19.3.1、TanStack Start 1.169.4、Vite 8.3.5、openapi-typescript 7.13.0を使用しました。

2026年10月31日に`limit`の数値化前の表記検査を追加し、指数・基数接頭辞・符号・空白付き表記を拒否しました。入力検査を外す変更と契約外のエラーコードを返す変更がテストで検出されることも確認しています。

2026年11月2日、契約と生成処理を`packages/api-contracts`と`tools/api-codegen`、画面・API・回帰テストを`apps/web`へ移しました。生成物を削除した状態から契約生成・型検査・テストが成功し、Void 1.4.0の開発・ビルド済みWorkerでHTTP契約28ケースとブラウザの一覧2件・再取得を確認しました。favicon未配置の404が残ります。一覧は架空データを使う暫定契約であり、正式な履歴API、一覧のSSR取得、認証情報の転送を検証したものではありません。

引き継ぐ互換性の制約は次のとおりです。

- openapi-typescriptはTypeScript 5系のCompiler APIを使います。7.0.2では型生成に失敗したため、生成専用の`tools/api-codegen`を5.9.3に固定し、アプリの型検査は7.0.2に分離しました。
- Cloudflare Viteプラグイン1.66.0では開発時に`Parent environment not initialized`が発生しました。1.64.0では起動します。上流の原因は未特定です。
- CommonJS形式のAjv検証コードは開発時に`exports is not defined`で失敗したため、ES Modulesを事前生成します。実行時コンパイルは行いません。
- Babel経由のsemver 6.3.1はpnpmの信頼ポリシーに拒否されました。coreとhelper-compilation-targetsに限り、provenanceのある7.8.5へ置換しています。今回の比較・範囲判定とビルドを検証したもので、Babelの全機能の互換性を保証しません。

制約の原本は[仕様書の依存バージョンの制約](../spec/mvp.md#依存バージョンの制約)です。採用理由は[ADR 0006](../adr/0006-typespec-api-contracts.md)を参照してください。

## 接続と回復の観測

2026年11月3日、次の各検査をローカルランタイムで実施しました。業務ルールの単体テストでは時計を差し替えますが、下表のQueue配送・再試行・scheduledは実時間です。

| 検査                     | 実行形態                     | 観測結果                                                                                   |
| ------------------------ | ---------------------------- | ------------------------------------------------------------------------------------------ |
| 診断正常系               | 開発Worker・実HTTP           | DO保存、Queue自動配送、Consumer完了、D1結果のGET取得                                       |
| 一時失敗                 | 開発Worker・実時間           | 30秒以上待って2回目で成功                                                                  |
| 再試行枯渇               | 開発Worker・実時間           | 30・120・300秒以上の待機後、全4回失敗と実DLQ受信                                           |
| 受付応答消失             | 開発Worker・実HTTP           | 同じ要求の再送でジョブと初期化outboxを各1件に維持                                          |
| 受付直後・DO保存後の停止 | 開発Worker・実再起動         | D1の送信待ちと60秒周期のscheduledから回復                                                  |
| Queue送信直後の停止      | 開発Worker・実再起動         | D1の送信待ちから再送し、業務試行の重複を防止                                               |
| 結果保存後ack前          | 開発Worker・呼び出し例外     | Queueが同一メッセージを再配送し、完了済み結果を維持してack。その後の実再起動でも結果を保持 |
| 通常Queue・DLQ           | 開発Worker・テスト専用評価器 | WebとInterviewから同じ環境のEvaluationへ配送。通常DLQも受信                                |
| Queue固有の再試行        | 開発Worker・実時間           | 通常配送4回とDLQ1回、配送間隔30秒以上をDBで検査                                            |
| HTTP契約                 | 開発・ビルド済みWorker       | 一覧28ケース、診断20ケースをそれぞれ生成契約に照合                                         |
| 並列環境の分離           | 開発Worker・test環境2つ      | D1・DO・Queue・出力の分離と、開発10テーブル・生成物の不変を確認                            |
| プロセス終了             | ローカル実プロセス           | 起動元SIGKILL、Vite異常終了、中断・期限切れで所有する子プロセスの終了とロック解放順を確認  |

診断画面も同日、正常1回・再試行成功2回・全4回失敗とDLQの表示をブラウザで確認しました。応答消失後の同じ要求の再送、再送中の重複操作防止、契約外応答の拒否を確認しています。本番向け成果物はローカルでビルドし、診断モジュール・ルート・バインディングの除外と診断HTTP入口の404を検査しています。

2026年11月3日のタスク9全体検査では6ファイル・15ケースが500.87秒で成功しました。再試行枯渇の試行間隔は30,010・120,016・300,019ミリ秒、scheduledは7回成功しました。実行IDは`84bbe1aa-fd3b-4e92-99d3-585fdad022e1`です。開発・ビルド済みの各HTTP結果を分けて数えると、全体で17件の結果ファイルがあり、すべて終了コード0でした。

旧試作削除後も同日に全体検査を再実行し、通常検査と文書63件、統合6ファイル・15ケース（500.28秒）が成功しました。実行ID`6dcd6eda-cd7a-4492-934c-cb4cf4e29717`の再試行間隔は30,010・120,016・300,022ミリ秒、scheduledは7回成功しました。17件の結果が終了コード0で、開発データと生成物の不変も確認しました。旧試作の項目削除後のロックファイルSHA256は`219a79d471dd79b855eb2437becebab56a1e3074ea7720fac6b01188a2f41950`です。

統合検査の証拠は`.local/tests/{実行ID}/{並列番号}/results.json`に保存します。正常終了時も証拠は残します。固定版、環境、期待値、実測値、終了コードを記録し、入力本文や秘密値は含めません。CIは既存の`Documentation checks`内に20分上限の独立ジョブを追加しています。GitHub Actions上の実行結果は未確認です。

## ローカル検証の限界

固定版MiniflareのQueueはメモリ内に未配送メッセージを持ち、ランタイム全体の停止をまたいで保持しません。結果保存後ack前の試験はConsumer呼び出しの例外による再配送を検査しています。プロセス全体をack前に終了してQueueの永続性を証明したものではありません。Queue送信直後の停止からの回復はD1 outboxによるものです。

クラウドのreplica遅延、認可、実AI、長期障害後のDLQ保持・運用回復は未検証です。正式な面接・評価機能とクラウドへの配置は後続範囲です。未確認事項は[仕様書の補足事項](../spec/mvp.md#補足事項)へ集約します。
