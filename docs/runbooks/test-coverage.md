# テストカバレッジを計測する

既存テストで実行した範囲と、100%に向けて調べる箇所を確認するための手順です。

## 全体計測と100%判定

`pnpm test:coverage`はAPI生成、API型生成ツールのNode.jsテスト、保持確認の準備、通常・結合・実時間テストを実行し、Node子プロセスと実Workerを共通台帳へ収集します。`pnpm check:coverage`は現在のソース・対象集合・計測形式と照合し、各対象ファイルの行・文・関数・分岐の100%を実数で要求します。失敗・未完了・欠落した収集は受理しません。

出力は`coverage/combined/index.html`・`coverage/combined/files.json`・`coverage/combined/missing.json`です。対象選択は[対象台帳の定義](../../tools/coverage/src/targets.ts)、結果と除外理由は[調査記録](../research/test-coverage.md)を参照してください。生成物・型宣言・テスト専用コードを除外し、未importの手書き実行コードと実行式を持つ設定ファイルも台帳に残します。要素がない個別ファイルは理由付きで記録し、到達済みとは数えません。

通常CIの分割は維持し、全体計測と閾値検査は`Worker real-time checks`の長時間ジョブで実行します。文書だけのPRでは省略し、コード変更のPR・夜間・手動実行で検査します。API型生成器のCompiler API分離、Guard設定、実時間テストの選択もmainの構成を維持します。

## Node限定の補助計測

以下は従来のV8計測です。全体100%の判定には使用しません。

### 実行と結果

依存をインストールした後、リポジトリルートで実行します。

```sh
pnpm test:coverage:node
```

契約を生成してから、API型生成ツールのNode.js互換性テストと、通常の`pnpm test`が選ぶVitestテスト群を実行します。カバレッジを収集するのはVitest側です。ローカルHTTP・Unixソケット・Worker起動を許可した環境が必要です。パッケージ間は直列、各パッケージ内は最大2ワーカーに抑えます。既存の通常テスト・CIの実行方法は変更していません。

終了コード0と、テスト失敗・未処理エラーがないことを確認してください。失敗した実行の数値は基準値に使いません。出力先の`coverage/node`は実行開始時に清掃されるため、同時実行しないでください。

| 出力                                  | 用途                                    |
| ------------------------------------- | --------------------------------------- |
| `coverage/node/index.html`            | ファイル別の未実行行・分岐を見る        |
| `coverage/node/coverage-summary.json` | 全体・ファイル別の4指標と件数を取得する |
| `coverage/node/coverage-final.json`   | 文・関数・分岐の位置と実行回数を調べる  |
| `coverage/node/lcov.info`             | 対応エディタや外部レポートツールで読む  |

レポートはGit管理対象外です。調査記録には計測日、対象リビジョン、テスト件数、指標ごとの分母・実行済み件数を残します。各ファイルの割合の単純平均ではなく、件数を合計して比較します。

### 集計対象と限界

[専用設定](../../vitest.coverage.config.mts)が対象範囲の正本です。アプリの`src`・`scripts`、共有パッケージの`src`・`db`・`scripts`、開発ツールのTypeScriptを含め、未importファイルも分母へ含めます。生成コード、型宣言、テスト、fixture、設定ファイル、依存ライブラリは除外します。SQL・TypeSpec・YAML・CSSはこのJavaScript計測の対象外です。DBのテスト補助コードも対象外です。

行・文・関数・分岐を計測します。現状把握の段階では閾値を強制しません。テスト対象の欠落を除外設定で隠したり、計測値のためだけに既存テストを重複追加したりしないでください。

**このレポートはVitestのNodeプロセスで観測した範囲です。** HTTP先のWorker、生成CLIや隔離検査の子プロセス、API型生成ツールのNode.jsテスト、実ブラウザの実行回数は収集しません。そこで実行されるファイルにも0%が表示されるため、0%だけで「テストがない」と判断できません。WorkerとNodeの両方で使うコードも、Worker側の実行分は未計測です。

通常テストから分離されている結合・実時間テスト8ファイルも本コマンドでは実行しません。`pnpm test:integration`の結果は別の検証として扱い、その実行だけでこのレポートに加算されたとは扱いません。

ローカル境界テストは既存の`selectTestFiles('boundary')`を使い、通常テストと選択を共有します。新しいパッケージを追加する際は、専用設定の`projects`とテスト選択も更新します。アプリ単独のVite設定を読み込まないため、今後テストのsetupやaliasを追加する際には計測側との整合性も確認してください。

### 不足箇所の調べ方

1. HTMLで未実行の行・分岐を開きます。
2. 既存のテストから、Node・Worker・子プロセスのどこで動くかを確認します。
3. Node側で計測できている処理は、不足する入力・境界値・失敗条件を仕様と照合します。
4. Worker・子プロセス側は先に計測経路を整備し、既存テストの実行分を回収します。
5. 本当に不足するテストを1件ずつRed/Greenで追加します。行を通すだけでなく、戻り値・保存結果・副作用を検証します。

V8方式を既存Vitestへ追加する構成です。Workers Vitest統合ではV8方式は非対応でIstanbul方式が必要と[Cloudflare公式資料](https://developers.cloudflare.com/workers/testing/vitest-integration/known-issues/)に記載されています。既存の別プロセスWorkerへproviderを変更するだけでは計測できません。Workerでの計装・回収・元ソースへの対応付けと、Node側結果との統合を別途検証する必要があります。
