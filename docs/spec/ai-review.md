# AIレビューのコメントと修正確認

`tools/ai-review`がGitHubのPRへ投稿する指摘と、その修正確認の要件です。2026年10月25日に追加しました。既存の実行条件と権限分離は[導入設計](../research/ai-code-review.md)に従います。

更新ごとに新しい集約コメントを投稿し、元の指摘と確認結果の履歴を残す実装です。ローカルの自動検査を行い、実PRでの動作はmain反映後に確認します。

## 指摘の投稿

- AIレビューで採用した指摘を、対象のGitHub PRへコメントとして投稿する。
- 各指摘には対象箇所、発生条件、影響、修正方針を含め、どのコミットをレビューした結果か分かるようにする。
- 再レビューでも元の指摘を残し、指摘ごとに修正確認の結果を対応付けて追記する。同じ指摘を新規の指摘として重複投稿しない。

## 修正確認

PR更新後、通常CIの成功を受けて再レビューするときに、過去の指摘についても対象コミットのコード・文書を確認する。

| 判定                                 | 追加する文言             |
| ------------------------------------ | ------------------------ |
| 指摘した問題の修正を確認できた       | `☑️: 修正を確認しました` |
| 指摘した問題の修正を確認できなかった | `修正が確認できません`   |

確認結果には対象コミットと判断の根拠を添える。資料不足などで判断できない場合も「修正が確認できません」とし、未修正を確認した場合と区別できる理由を書く。新しいレビューで指摘が出なかったことや、通常CIが成功したことだけでは修正済みと判定しない。

モデル呼び出しの失敗などで修正確認自体を実行できなかった場合は、修正判定を追加せず、実行を未完了として扱う。投稿直前に対象コミットが変わっていた場合も、古い確認結果を投稿しない。同じ対象コミットに対する同じ指摘の確認結果は、再実行しても重複投稿しない。

## 受け入れ条件

1. AIレビューの指摘を対象PRのコメントで確認できる。
2. 指摘への修正を含むPR更新後、元の指摘に対応する「☑️: 修正を確認しました」と確認根拠が追加される。
3. 修正を確認できないPR更新後、元の指摘に対応する「修正が確認できません」と理由が追加される。
4. 再レビュー後も元の指摘と過去の確認結果が残り、どのコミットに対する判定か分かる。
5. 再実行、資料不足、モデル失敗、投稿前のPR更新によって、重複投稿や誤った修正済みの表示が生じない。

確認結果は新しい集約コメントに記載し、元コメントへのリンクと指摘番号を付ける。既存形式の集約コメントも修正確認の対象にする。過去の指摘は最大30件まで扱い、超過・破損・取得失敗は未完了として停止する。新規指摘の最大3件とは別枠で全件を確認する。

件数にかかわらず、コードなどを含むJSON資料全体は既存の400KB上限を維持する。履歴を含むmetadataも400KBまでとする。容量超過時は未完了で停止し、過去の指摘を黙って省略しない。重複はモデルに既存指摘との意味上の対応付けを指示し、同じファイル・発生条件の指摘は投稿前の検証でも拒否する。
