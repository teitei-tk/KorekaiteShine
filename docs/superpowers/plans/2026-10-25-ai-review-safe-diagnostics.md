# PR終了確認とAIレビューの安全な診断の実装計画

> 実装は`superpowers:executing-plans`に従い、この作業内で順に行う。

**目的:** 作成したPRの整理漏れを防ぎ、AIレビューが未完了になった原因を秘密値・モデル生出力なしで判別する。

**構成:** 既存の失敗理由に固定サブコードと不足情報分類を追加する。子プロセスでは診断分類だけを受け渡し、親が検証済み台帳から資料範囲を付与する。既存の4KB状態ArtifactとActions概要、PRの表示ジョブへ引き継ぐ。

**技術:** 既存のTypeScript・Vitest・JSON Schema。追加依存・権限変更なし。

**仕様:** 利用者が承認した振り返りの2項目と[AIレビュー仕様](../../spec/ai-review.md)。

## 設計判断

自由文のエラーやモデルの不明点をそのまま記録すると、認証値・資料本文・任意文字列を出力する可能性があるため採用しない。固定分類だけでは作業範囲を特定しにくいため、資料ID・行範囲・リビジョン種別・件数を併記する。資料のパスや本文は記録しない。範囲は最大8件ずつとし、全件数から省略を判断できるようにする。

モデル申告の資料不足は検証済みの事実とは扱わない。旧形式の状態Artifactは読み続け、診断がない失敗には既存理由を表示する。未完了の部分結果は投稿しない。

## 手順と完了条件

- [x] 作業手順にPRの最終状態・残す理由・テスト移管先の確認を追加し、AGENTS.mdの参照条件へPR終了時を加える。
- [x] 固定診断の検証・資料範囲・上限・未知の値拒否のテストを先に失敗させ、診断型と変換を実装する。
- [x] API・モデル検証・子プロセス境界から親の失敗報告までを接続し、秘密文字列が記録されないテストを通す。
- [x] 状態ArtifactとPRチェックの表示へ接続し、旧形式互換・改ざん拒否・4KB上限のテストを通す。
- [x] 仕様・運用手順を更新し、全体検査と独立レビューを行う。

## レビュー重点

APIの生成中断とモデルの未完了申告の区別、モデル申告の自由文混入、台帳検証前の情報漏洩、旧形式との互換、上限超過による本来の失敗理由の消失を確認する。PRのクローズは承認範囲内に限り、Resolveは操作しない。今回は実装・検証までとし、既存PRの操作は行わない。

## 検証結果

`pnpm check`で221テスト・Lint・整形・型検査・文書検査が成功した。独立レビューのP1/P2指摘は0件。実API・実PRでの表示確認は未実施。実装後の利用者の依頼により、コミット・pushとPR作成を行う。既存PRのマージ・クローズやResolve操作は行わない。
