# AIレビューの担当範囲と補助資料の実装計画

承認された案②を実装する。既存の分割設計を更新し、各確認対象に必要な補助資料を固定する。

## 目的と構成

確認対象の原文と判断用の補助資料を台帳で区別し、双方を同じ担当作業へ渡す。単位確認は変更箇所、横断確認は指定した関係、履歴確認は過去指摘を担当する。未確認事項の後続委譲や成功への補正は追加しない。

仕様は[分割設計](../../spec/ai-review-partitioning.md)。TypeScriptの既存収集・分割・検証・プロンプトを変更し、新規依存は追加しない。

## 実装順序

- [x] `partition.ts`で補助資料IDを確認対象へ固定し、担当作業に同梱する。直接の参照元・参照先と領域規約を選び、一般依存の再帰展開はしない。
- [x] 補助資料をハッシュ・容量・資料包含の検証対象にし、省略や不正IDを事前拒否する。単独でも収まらなければ未完了にする。
- [x] `partition-review.ts`と`prompt.md`で担当範囲を明示する。単位作業へPR全体の結論を要求しない。自分の判断に必要な資料不足は停止する。
- [x] 呼び出し元・依存先・規約、改変、容量超過、作業間の引継ぎなしを回帰テストで確認する。
- [x] PR #30の固定SHAで入力を再構成し、旧版で不足した資料が前段へ渡ることと容量内であることを確認する。`pnpm check`を実行する。

## 制約と確認点

1回の原文300KB・JSON資料400KB・プロンプト500KBと実行ごとの$1予算・30分制限を維持する。Resolveは操作しない。PRコードの実行・モデルへのツール付与を追加しない。規約の参照先から無関係な全ファイルへ展開しない。base/head両版を扱い、補助資料の存在を実際の確認完了の証明と混同しない。
