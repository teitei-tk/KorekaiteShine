# AIレビューのトークン・費用制御への移行計画

> 実装担当は `superpowers:executing-plans` を使い、各段階の回帰テストと実データ検証を行う。

**目的:** 固定バイト数でレビューを拒否せず、実要求の計数、実行ごとの$1、処理期限で制御する。

**構成:** 関連単位・横断・履歴の担当範囲と出力形式検証を維持する。バイト数は観測値に限定し、収集・モデル呼び出し・IPC・成果物読み直しに残る拒否条件を除去する。要求の実トークン数を計数APIで取得し、最大出力を含む費用予約の承認後だけ生成する。

**技術:** Node.js、TypeScript、OpenAI SDK、Vitest。依存追加なし。

**仕様:** 最新の利用者指示と[監査記録](../../research/ai-review-limit-audit.md)。旧仕様の固定容量維持方針を更新する。

## 共通条件

- 生成実行ごとに$1。予算超過はPRコメントで通知し、CIエラーとしない。
- 30分の生成期限、要求単位のタイムアウト、権限分離を維持する。
- モデルのトークン上限と出力Schemaの制約を、料金・バイト数と混同しない。
- Resolveは操作しない。main反映前の実行を修正版の検証済みとしない。

## 実装と検証

### 1. バイト制限を全経路から除去する

対象: material、source-index、partition、partition-review、review、orchestrate、artifact、budget、budget-publish、publish、status-report。

- [x] 旧上限を超える入力・出力・成果物の失敗テストを先に追加する。
- [x] Git本文取得は一時ファイルへの出力で固定maxBufferを廃止する。索引と資料結合は固定バイト数に依存させない。
- [x] 形式検証・ハッシュ照合を保持して固定サイズの拒否を除去する。保存側と読み込み側を同時に変更する。
- [x] 料金判定前のサイズ拒否、料金精算後の出力サイズ拒否を除去する。

### 2. 費用・トークン・時間の回帰テスト

対象: review、budget、partition-review、orchestrate、artifact、publishのテスト。

- [x] 日本語・ASCII・エスケープで旧バイト上限を超える資料でも、計数・予約・生成・精算が正しい順序で行われる。
- [x] 小さい資料でも$1を超える予約は生成前に停止し、予算通知へ渡す。
- [x] 保存と投稿側の再検証、期限超過、不正出力時のusage保持を確認する。
- [x] モデルのトークン上限を超えた要求を料金超過と偽らず停止する。

## 特に確認する失敗条件

- 入口は許可するのにArtifactの読み直しで拒否される。
- 計数に失敗した場合や料金未精算の場合にモデルを追加実行する。
- 過去指摘が多い時に応答バイト数を理由に課金後に失敗する。
- 巨大な関連資料が同じ確認対象へ集中し、単一作業がトークン上限を超える。
- 大規模PRで件数制限・Schema・タイムアウトが別の隠れた制限になる。

## 完了条件

ローカルテストだけでは完了にしない。同規模の実レビューが最後まで成功した証拠を必要とする。失敗した場合は原因と未完了範囲を記録し、成功とは報告しない。

## 実装中の確認記録

- PR #30固定資料のテストが旧300KB制限で失敗することを確認し、除去後に通過した。
- 独立レビューで、子作業に渡していない資料の引用を親の範囲で受理する問題を発見。子ごとの担当IDと根拠で検証する回帰テストをRED→GREENにした。
- 独立レビューで、無条件結合が宣言境界を失わせる問題を発見。原文の宣言境界を保持する回帰テストをRED→GREENにした。
- 判断: 横断対象は宣言の直積ではなく参照ファイル対ごとの契約とする。両側の全原文は保持する。宣言境界を保持すると同じファイル契約の直積が5,000件を超えるため、重複登録を取り除いた。単一契約の必須文脈がトークン上限を超える場合は未完了として通知する。
- PR #30統合テストは実資料の複数段階の検証で約6秒かかるため、このテストだけ30秒のテスト期限を設定する。製品の処理期限や費用上限は緩和しない。
