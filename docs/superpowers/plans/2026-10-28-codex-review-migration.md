# 公式Codex ActionへのAIレビュー移行計画

> 実装担当は`superpowers:executing-plans`を使い、各段階の成立を確認してから次へ進む。

**目的:** 現行WIFを維持し、独自レビューエンジンを公式Codex ActionとWIFプロキシへ置き換える。

**構成:** 準備・履歴・投稿は既存TypeScript基盤を再利用する。探索と認証交換・更新は公式実装に任せる。

**技術:** TypeScript、Node.js、Vitest、GitHub Actions、Codex Action v1.13、Codex 0.164.0。

**設計:** [承認済み設計](../specs/2026-10-27-existing-review-wif-design.md)。2026年10月28日に利用者が実装開始を指示した。

## 共通条件

- 公式`unprivileged-user`と読み取り専用設定を使う。PRコードの実行はこの境界内だけで許容する。
- 実資格情報を使わない隔離検証、WIF接続検証、レビュー・投稿の順を守る。前段の未成立を後段の大量実装で埋めない。
- 現行Provider・サービスアカウント・OIDC条件を広げない。APIキー、独自DB、監視基盤、認証プロキシ、実行ラッパーは追加しない。
- 新規指摘3件、過去指摘30件。旧返信数・容量・ページ数上限と$1厳密上限は新方式では廃止する。
- 投稿再開は固定Artifactと保持されたGitHubコメントを使う。削除後の同一Artifact再試行は保証しない。
- 作業は現在の隔離worktreeで行う。リモートへの公開・現行Workflowの切替と、有料検証は別途扱う。

## レビュー重点

- 別UIDの環境だけでなく親プロセス・保護ファイル・サービスソケットにも到達できないか。
- PRの設定や子プロセスから書込み・通信制限を回避できないか。
- APIの末尾取得失敗を部分履歴として採用しないか。
- 応答喪失後の自己投稿を除外でき、人間の編集・返信・Resolve変更を除外しないか。
- 投稿再試行時に生成を再実行せず、手動削除後の限界を誤表示しないか。

## Task 1: 資格情報を使わない隔離検証

**ファイル:** `tools/ai-review/isolation-probe.ts`、対応テスト、`tools/ai-review/isolation/`の検証用fixture・手順。

**境界:** 公式Actionの別UID起動と公式CLIのLinux sandboxをそれぞれ実行して観測する。検証用代替実行ファイルはActionの環境検査専用とし、本番レビューには使わない。模擬値以外の資格情報を投入しない。

- [x] 模擬資格情報漏洩、保護ファイル・親プロセス読取り、書込み、昇格、通信を検知する検査を先に追加し、無制限環境で失敗を確認する。
- [x] 専用UID、sudoの環境初期化、root所有設定を用意し、公式CLIの読み取り専用sandboxで検査する。
- [x] Actionの固定版ヘルパーを改変せず、専用の検証用実行ファイルを通して環境非継承と起動引数を確認する。
- [x] GitHub-hosted runnerとローカルコンテナの証拠を区別する。実runnerで成立するまで後段へ進めない。

2026年10月29日、実runnerの認証ファイル候補・プロセス・既知の特権ソケットと、実CLIのオフライン起動まで追加検証した。[検証結果と範囲](../../../tools/ai-review/isolation/README.md)を参照する。Task 1の成立はTask 2の実接続・有料検証を実施済みとするものではない。その後、利用者がPR #43のマージとmainでの隔離検証成功を条件に、実WIF接続検証を承認した。有料モデル呼び出しは引き続き行わない。

検査: `pnpm --dir tools/ai-review test isolation-probe.test.ts`とLinuxでのfixture実行。期待値: 許可した読み取り・PR fixture実行だけ成功し、禁止操作はすべて拒否。

## Task 2: 公式WIFプロキシとActionの接続

**前提:** Task 1の実runner検証に成功している。

2026年10月29日、利用者の指示により実資格情報を使わない事前確認だけを追加した。公式ActionのAPI-key入力を空にする経路を全体実行し、模擬キーをパイプで受け取る公式プロキシの配置・メモリ隔離、通常終了とAction失敗後の停止を実runnerで確認した。[証拠と限定](../../../tools/ai-review/isolation/README.md)を参照する。固定版Actionにプロキシ用の独自postはないため、呼出し側の`always()`から公式終了APIを使う。以下の実WIF交換・更新、実モデルとSchemaの項目は未完了のままとする。

実WIFの初期交換だけを確認するジョブを既存の`ai-review.yml`に追加する。限定マッピングに合わせ、mainの`workflow_run`からのみ実行する。`AI_REVIEW_MODE=off`と、指定されたmainのCI実行IDが両方一致した場合に限定する。認証後は既存のUID・読取り専用・proc・環境隔離検査と公式終了APIを使い、モデル要求は送らない。準備処理と隔離検査はTask 1のものを再利用し、交換・更新プロトコルの独自実装は追加しない。実行手順と未検証範囲は[運用手順](../../runbooks/ai-review.md#モデルを呼ばない公式wif接続検証)に記録する。

**ファイル:** `.github/workflows/ai-review.yml`、`tools/ai-review`内の小さなプロキシ起動・終了処理、対応テスト。

**境界:** 既存クレーム検査を再利用し、公式プロキシへ標準入力のパイプで要求資格情報を渡す。専用HOMEの信頼する設定とserver-infoでActionを接続する。

- [ ] 起動失敗・期限更新失敗・終了処理の検査を追加して失敗を確認する。
- [ ] 公式起動・接続処理だけを追加し、小さなSchema出力を検証する。
- [ ] 実runnerで非継承、既存マッピング、モデル、更新・終了を確認する。料金・利用量の欠損をゼロとして記録しない。

- [ ] 長い履歴、全件ページ取得、履歴改訂、途中投稿・応答喪失・手動削除の回帰テストを追加し、失敗を確認する。
- [ ] 固定Artifactと単一投稿器へ置換し、分割・課金予約・独自再生成処理を削除する。
- [ ] 通常検査、Actionsロック、独立レビューを実施する。公開前に未検証事項を整理する。
