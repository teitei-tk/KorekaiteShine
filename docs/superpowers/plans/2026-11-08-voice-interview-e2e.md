# 音声面接のブラウザE2E実装計画

利用者が開始ボタンを押してから、返答を聞き、切断後も同じ面接で会話できることを検証する。[受け入れ条件の原本](../../../tools/e2e/features/voice-interview.feature)をCucumber.jsで直接読み、ステップからPlaywrightでChromiumを操作する。業務要件は[MVP仕様書](../../spec/mvp.md)、音声の中継と再開は[ADR 0001](../../adr/0001-server-relayed-interviews.md)、環境分離は[ADR 0009](../../adr/0009-explicit-environments.md)に従う。HTTP・Queueの型は引き続きTypeSpecが原本となる。

## 1. 対象を固定して失敗を記録する

- [ ] この計画の作業ツリーは fec4683。参照チャットの面接実装は別作業ツリー 67aa の 09ea4a1 と作業差分にある。実装開始時に後者の状態を確認し、修正版と各不具合が存在した版を再現可能なコミットまたはパッチで特定する。現作業ツリーに画面がないことで失敗した結果は回帰の証拠に含めない。
- [ ] tools/e2e にランナー、ステップ、架空のMarkdownと合成発話を置く。通常CIは実行単位の APP_ENV=test で既存のローカル起動基盤からWeb・面接DO・評価Workerを起動する。DB、ポート、ブラウザコンテキストを分離する。準備も画面のファイル選択・分析・テーマ選択を経由する。
- [ ] 外部AIの境界だけをテスト用サービスに差し替える。入力音声を受けてから識別可能な非無音の返答と確定テキストを返す。最初の返答には過去に誤判定したID省略形を含める。ブラウザのマイク入力、WebSocket、音声デコード、再生、DO、保存は実経路を通す。
- [ ] 最初のシナリオから1件ずつ実装する。修正前の同じ画面で該当するThenが失敗し、修正版で同一ステップが成功することを記録する。旧版が取得できない場合は隔離したコピーで当該不具合だけを戻し、故障注入による検証と明記する。未定義ステップや起動失敗はRedに数えない。

## 2. 音声、利用枠、再接続の判定を実装する

- [ ] Chromiumの仮想マイクに合成発話を入力する。返答ごとにブラウザの実再生経路で音声サンプルの非無音区間と再生時計の進行を観測する。開始表示、受信フレーム数だけで合格にしない。履歴を開き直し、面接IDと双方の確定テキストを照合する。
- [ ] 接続拒否を3回注入し、各試行後に同じ日の残量を読み直す。時間計測では面接中・一時停止・再接続待ちの遷移を単調時計で記録し、表示丸めと観測遅延の許容幅を先に固定する。各待機区間を許容幅より長く取り、誤計上を検出できるようにする。
- [ ] 回線切断はブラウザとWeb間で発話中に起こす。再起動ケースは永続状態と公開URLを維持して接続情報を更新する。どちらも開いたタブで復帰操作を行う。新しい応答を切断前の音声と区別し、確定済みの発言をIDまたは内容と回数で照合する。発話途中の未確定部分の完全復元は要求しない。

## 3. 同じ原本からCIと実AI確認を実行する

- [ ] ルートに test:e2e と test:e2e:live を追加する。前者はPRで @pr 全件を実行し、後者は明示起動で @live を実AIに接続する。ステップと判定を共有し、接続先と入力だけを実行プロファイルで切り替える。実AIの文言は固定せず、発話後の新規応答と双方の確定発言を確認する。
- [ ] CIは対象0件、未定義・曖昧・保留・スキップを失敗にする。シナリオ名、失敗ステップ、対象版、接続種別、状態遷移と所要時間を残す。音声、秘密値、セッション情報は成果物に含めない。各ケースに期限を設け、自動リトライで初回失敗を隠さない。
- [ ] 通常の pnpm test、pnpm check と既存の結合検査を実行する。ローカル結合検査にファイルを追加する場合は tools/local-integration/src/test-suites.ts に登録する。完了報告に旧版の失敗、新版の成功、実AIで実行したシナリオを対応付ける。物理マイクとスピーカーの聞こえ方は最後に実機で確認して別記する。
