# 長時間カバレッジ検査の並列化計画

既存PRのCI高速化として実施する。実時間30・120・300秒の再試行と実DLQ、全ファイルの4指標100%を維持する。

## 設計と選択理由

1台のワーカー数だけ増やす案はCPU・メモリ競合を増やす。実時間待機の短縮は検査目的を失う。そのためVitestの全ファイルを4台へ分割し、各台の最大2ワーカーを維持する。生成・準備・buildは各台で実行し、状態を共有しない。実装はこのセッションで行う。

シャードごとに台帳と完了済み計測片を保存する。統合時は4件の番号、対象revision、全対象と計測位置、必須suite、収集完了を照合し、既存の統合処理と100%判定を使う。欠落・重複・古い成果物を拒否する。依存は既存の保護付きstoreキャッシュを再利用する。

## 実装手順

- [x] `tools/coverage/tests/shards.test.ts`で分割された実行回数の統合、欠落・重複・revision不一致・失敗片の拒否をRedで確認する。
- [x] `tools/coverage/src/shards.ts`と`run.ts`に4分割の収集・統合入口を追加しGreenを確認する。
- [x] `collect.ts`でsuiteの開始・終了・経過時間を出力する。
- [x] `ci-realtime.yml`を4台の収集と独立した統合へ変更し、失敗・欠落時の集約失敗を維持する。Actionsロックを再生成する。
- [ ] lint・型・通常検査・文書検査とレビューを実施し、同じPRで実runnerの全体時間・100%判定を確認する。

## 確認する境界

空・不足・重複のシャード、別revision・対象ソース・計測形式の混在、子プロセス未完了、シャード失敗時の結果集約、実時間テストが1回だけ選択されることを確認する。成功まで性能改善率を断定しない。
