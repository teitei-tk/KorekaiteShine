# 境界テストの処理別計測

## 目的と範囲

run 44516893055で遅かったcheck-object、dlq、delivery-anomalies、topology、diagnostics、production-artifactsの6ファイルを、同じ通常CIで計測する。検査内容・並列度・待機条件を変更しない。

## 計測方法

テスト専用helperで単調時計を使い、各ケースのランタイム起動完了まで、明示的なDBコマンド、ビルド、終了を計測する。残りを検証等とする。検証等にはHTTP、scheduled呼出、assertion、ファイル準備・削除などを含み、assertionだけの時間ではない。起動・ビルド内部のDB処理はその呼出全体に含める。

AsyncLocalStorageでケースごとの計測を分離する。重なる呼出区間は和集合で控除し、カテゴリ間の重複時間も記録する。失敗時もfinallyで計測し、戻り値・例外・停止動作を維持する。出力は固定ファイル名・ケース番号・数値のみとし、SQL、要求、応答、実行ID、エラーメッセージを含めない。

## 検証

計測の成功・失敗・重複区間を単体検査し、suite所属・lint・型・整形・文書を確認する。通常CIで6ファイルすべて成功した結果を集計し、起動・DB・ビルド・検証等・終了の比率を報告する。ローカルの既知のWorker停止タイムアウトと実CIの結果を区別する。
