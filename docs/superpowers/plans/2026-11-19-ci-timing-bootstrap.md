# 実測時間の初期配分と再起動検査の計測

## 設計

main成功履歴がまだないPRでも実測配分を使う。確認済み通常CI run 44344193908の全結果を、測定元run・attempt・head・日時を付けた初期値としてリポジトリで管理する。main履歴を優先し、不足するIDだけ初期値で補う。初期値もrepository・workflow・実行条件・30日期限・正の有限時間を検証する。PR artifactの自動信頼への拡張は行わない。初期値・履歴とも使えない場合は従来の均一重みとする。対象選択・合否・Guardは変更しない。

代替はmainマージまで均一配分を続ける方法とPR履歴の自動取得だが、今回は同じPRで実測配分を検証でき、出所をレビューできる固定初期値を採用する。初期値更新には成功runの全結果と計画の照合が必要となる。

## 実装順序

1. main優先・初期値補完・不一致・期限切れ・破損・全対象保持の回帰検査をRed/Greenで追加する。
2. 成功runの計画と全シャードを照合して初期値を作成し、CLIの配分と予測時間へ同じ重みを渡す。計画の理由に使用した出所を記録する。
3. 診断シナリオに初回起動・再起動・検査と待機・終了処理の単調時計による時間を追加し、再起動テスト5件で数値だけを出力する。既存の実時間待機・検証を維持する。
4. 通常検査・文書検査・CIで全対象の実行、配分変化、再起動5ケースの時間内訳を確認する。

## 受入条件

初期値で全選択テストを重複・欠落なく配分し、main成功履歴があるIDはそちらを優先する。再起動検査の60秒待機3回と30秒再配送1回は保持する。実測比較は準備時間とテスト本体を分け、同一条件の反復測定ではないことを明示する。
