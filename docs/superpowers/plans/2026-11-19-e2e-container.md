# E2Eブラウザ準備のコンテナ化

## 合意した設計

通常CIのE2E 4シャードだけを公式Playwright 1.65.1 Nobleコンテナで実行する。タグとmanifest digestで固定し、ブラウザとOSパッケージの毎回のインストールを削除する。他のテストはホストrunnerで実行する。

`--init`で子プロセスを回収し、Chromium用に共有メモリ1 GiBを割り当てる。runステップはbashで実行する。Nodeは引き続き`.node-version`から準備し、Guard・固定lockfile・信頼ポリシーの毎回の検証と既存のstoreキャッシュを維持する。

## 実装と検証

1. testsジョブにE2E限定のコンテナを設定する。
2. インストールを、イメージ内のPlaywright版と依存版の一致検査、Chromiumの起動・終了確認に置き換える。不一致や不足時は失敗し、追加ダウンロードで補わない。
3. Actions lockを公式ツールで生成・検証し、通常検査と文書検査を実行する。
4. 同じPRでCIを実行し、19シナリオの成功を確認する。コンテナ初期化・ブラウザ確認・ジョブ全体を測り、従来のブラウザ準備315秒と比較する。

## 更新手順と制約

Playwright更新時は`tools/e2e/package.json`とlockfileに加えて、workflow内の公式イメージのタグとdigestを更新する。レジストリのmanifest digestを確認し、CIでブラウザ起動とE2Eを再検証する。イメージの取得はnpm Guardの対象外であり、digestで内容を固定する。

ブラウザ以外も含む公式イメージの取得時間が発生するため、インストール削除だけを短縮効果として扱わない。ローカル環境のMCR blob取得は403で失敗したため、実コンテナ内の検証はGitHub Actionsで行う。
