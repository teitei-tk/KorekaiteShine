# 再起動5ケースの並列化

## 方針

直列だった再起動検査を1ケース1ファイルへ分割し、既存の時間配分と3つの結合シャードで並列実行する。各runnerの上限2 workerを維持する。同じrunnerで5ケース同時に起動する方式より、3 WorkersとViteの起動負荷を分散できる。

実行ごとのUUIDからWorker・DB・Queue・状態・成果物を分離する既存方式、ランタイムの動的ポート割当、個別の停止処理を維持する。60秒周期3ケースと30秒再配送の実時間検査、すべてのassertion、失敗時の証拠保存を変更しない。

## 手順と検証

1. suite所属の回帰検査で5ファイルの登録と旧ファイルの除去を確認する。
2. テスト本体を変更せず分割し、数値のみの計測helperを共有する。
3. run 44509486336の全成功結果と計画を照合し、初期実測値を更新する。旧ファイルの時間だけは同runの5ケースの計測値へ置換し、導出元を記録する。
4. 通常検査・文書検査・CIで254実行単位の欠落・重複なし、5ケースすべて成功、実時間待機維持と短縮効果を確認する。

## 比較基準

直列実行は同runで本体320秒、5ケースの計測合計318.8秒。CI全体は7分12秒。実行環境の変動があるため、同一条件の反復測定ではない。
