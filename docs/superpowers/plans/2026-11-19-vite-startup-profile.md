# Vite起動の内訳計測

## 目的と対象

既存PRの境界テストで、Viteプロセス開始からURL通知、URL通知から最初のHTTP本文受信の2区間を実測する。独立test環境のdev起動だけを対象にする。DB・テストの内容・並列度・依存保護は変えない。

## 計測方法

Viteの公開プラグインフックをラップし、同期値・非同期値・this・例外・フックのfilter/orderを保持する。設定解決時に組込みプラグインも対象にする。ただしViteが先に参照を取得する組込みconfigResolvedの実行と、設定モジュールのimport・プラグインfactoryはotherに残る。configureServerの先頭でCloudflare環境のinitRunner/fetchWorkerExportTypes、モジュールのfetchModule、Miniflare.ready/setOptions、依存optimizerを計測する。インストール済みの依存は編集しない。

同じホストの単調時計hrtimeで区間を合わせ、HTTP確認後に専用IPCでスナップショットを要求する。数値とプラグイン名・フック名だけをtest成果物に保存する。モジュールのパス・本文・要求内容は収集しない。終了・中断・IPCエラー・期限超過では失敗として既存の停止処理へ戻す。

時間はWorkerとモジュールの重複、Worker（モジュール処理を除く）、モジュール（Worker初期化を除く）、残るプラグイン、その他の優先順で排他的に分解する。Workerとモジュールの区間には親プラグインとの重複を含むが、プラグインの区間へは二重計上しない。フック別inclusive時間は並列・入れ子を含むため合算しない。resolve/load/transformはモジュール処理でありコンパイルCPU時間とは呼ばない。フックの外にあるCLI・設定モジュールのimport、Worker内の評価・HTTP処理等は未分類または親フックに残る。Miniflare.readyは準備待ちの観測区間でありコンストラクタの全時間ではない。

## 実行と検証

1. 重複区間集計とラップの意味保存をRed/Greenで検証する。
2. 管理プロセスへIPC収集を組み込み、終了・中断時の後処理を検証する。
3. lint・型・通常検査・文書検査と新しいコンテキストでのレビューを行う。
4. 同じPRの通常CIを実行し、54回のdev起動と計測件数を照合する。段階別平均と主要フックを報告する。

計測はwall時間であり計測自体のコストを含む。前回の未詳細計測と比較し、大きな増加があれば追加調査する。各snapshot後にフックの記録を停止し、検査本体への記録コストを避ける。
