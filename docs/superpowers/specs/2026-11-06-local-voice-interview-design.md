# 経験Markdownからローカル音声面接・評価までの設計案

2026年11月6日作成。利用者の依頼は、作成済みの経験Markdownを使い、ローカルで音声面接から評価まで一通り試せるようにすることです。同日、利用者から実装を優先し、モックを活用したテストを先に進める指示を受けました。本人のブラウザ・マイク操作と実AIによる確認は、実装と自動検査の後、最後にまとめて行います。

## 目的と到達点

本人がブラウザで経験Markdownを選び、送信内容を確認し、AIが提示したテーマを一つ選んで音声で話す。終了後に、保存済みの発言を根拠とする5軸の評価と振り返りを読める状態を作ります。固定応答だけのデモを完了条件にしません。

対象の原本はリポジトリ外の`/private/tmp/korekaite-materials/teitei-tk-com-experience.md`です。本人の担当・判断理由が未確認の下書きであることを材料の一部として扱い、本人の実績を推測で補いません。ファイルは変更せず、アプリのリポジトリやテストfixtureへコピーしません。

[MVP仕様](../../spec/mvp.md)と[用語集](../../../GLOSSARY.md)に従います。Cloudflareへの配置・リソース作成、GitHub材料の取り込み、長期の推移表示は今回の到達点に含めません。面接中の制御、記録保存、評価、失敗時の再実行は今回の経路に含めます。

## 実装方式と現在の差分

既に合意されている3 Workers・共有D1・DO音声中継・Queue評価を維持します。[ADR 0001](../../adr/0001-server-relayed-interviews.md)、[0002](../../adr/0002-queued-evaluation.md)、[0007](../../adr/0007-three-workers.md)、[0010](../../adr/0010-queue-contracts-and-job-control.md)が選定理由です。

| 方式                              | 利点と負担                                                               | 今回の扱い                   |
| --------------------------------- | ------------------------------------------------------------------------ | ---------------------------- |
| 既存の3 Workersへ正式な面接を実装 | 配送・実行権・回復を再利用できる。業務データと実AIアダプターの追加が必要 | 既存合意に沿う方式として提案 |
| 別のNodeアプリで音声と評価を実装  | 小さな接続試験には適するが、正式経路への再実装が必要                     | 採用しない                   |
| ブラウザから音声AIへ直接接続      | 中継の実装は減るが、DOで状態と送信権を管理する合意と異なる               | 採用しない                   |

現状の一覧は架空データです。InterviewとEvaluationの本番入口は空で、ローカルの診断入口だけが接続されています。評価の成功型も診断用の要約のみです。正式Queueのテスト専用Consumerが製品Consumerを横取りしないよう、検査経路も分け直します。診断処理の本番非包含は維持します。

## 画面と操作

1. 経験Markdownを選択し、全文・分量・送信先がOpenAIであることを表示する。明示的な「内容を確認してテーマを抽出」で初めてAIに送る。
2. 根拠の抜粋とともにテーマ候補を表示する。テーマを一つ選び、背景・担当・権限を任意で補足する。
3. マイクの許可と接続準備を確認して面接を開始する。現在の質問、文字起こし、面接時間、接続・保存の状態を表示する。
4. 一時停止・再開・言い換え・見送り・途中終了を操作できる。15分を目安に区切りを促し、提案上の上限20分で保存済み会話を評価する。
5. 終了受付後は評価状態を表示する。画面を閉じてもローカルランタイムが稼働していれば評価を進める。再度開くと保存済みの結果を取得する。
6. 5軸の点数または未確認・対象外、理由、参照発言、振り返りを表示する。根拠から会話へ移動できる。失敗理由と手動再実行を用意する。

正式な一覧は実データを取得し、診断データを混ぜません。今回の結果を後から開ける最小限の履歴と、面接単位の削除を含めます。追記メモ・推移グラフは後続とし、原文編集による評価入力の変更は提供しません。

## 契約と保存

HTTP契約は[ADR 0006](../../adr/0006-typespec-api-contracts.md)に従いTypeSpecから生成します。材料分析、面接作成・詳細・一覧・操作、評価再実行、削除を定義し、入力・成功・エラーを境界で検証します。既存の暫定一覧契約を無断で正式契約として流用しません。

WebSocketイベントとAI構造化出力もTypeSpecに原本を置き、JSON Schema・型・validatorを生成します。HTTP用OpenAPIとQueue本文の責務は変えません。音声はバイナリのPCM、操作・状態はJSONとし、ブラウザから上流APIの任意イベント・モデル・指示・接続URLを指定できないようにします。

DBの原本はDrizzleとし、[ADR 0008](../../adr/0008-shared-d1-with-void.md)に従ってVoid経由でマイグレーションを生成し、SQLを確認して適用します。既存データをリセットしません。追加する保存責務は次のとおりです。

- 材料分析：材料のハッシュ、選択候補と根拠の抜粋・見出し、モデルと指示の版。Markdown全文は分析時のメモリだけで扱い、ログ・リポジトリ・DBへ原本をコピーしない。
- 面接：本人識別、テーマと材料の固定抜粋、背景・担当・権限、状態、稼働時間、停止・再接続期限、接続の世代、作成・終了時刻。
- 発言：サーバー採番のIDと順序、話者、接続世代、受信した文字起こし断片と上流時刻。発言の表示上のまとまりと原文を分け、通信欠落と再生確認の範囲も保持する。
- 評価入力：面接終了時点の発言範囲、材料、採点基準、指示、モデルを固定し、評価ジョブへ結び付ける。評価中に元入力を変えない。
- 評価結果：5軸、根拠の発言IDと引用、振り返り、矛盾候補。既存のジョブ試行記録と実行権に結び付けて保存する。

本人につき進行中の面接は一つに制限し、競合する作成もDBの制約と条件付き更新で防ぎます。削除は実行権・ジョブ状態と競合しない条件で取り消し、関連する材料・発言・結果を削除し、遅延ジョブが復活させない識別情報を残します。

## 音声と面接状態

ブラウザのAudioWorkletでマイク音声を取得し、PCM16・24kHz・モノラルへ変換してWebSocketでWebからDOへ渡します。DOからGPT-Liveへは認証ヘッダー付きで接続し、秘密値はブラウザへ渡しません。上流の`session.started`を確認するまで音声を送らず、音声の送受信バッファには上限を設けます。録音ファイルや音声の永続保存はしません。

GPT-Liveの`store`はfalseです。音声モデルは`gpt-live-1`を初期案とし、材料分析・評価・面接中の推論委譲は明示設定されたResponses対応モデルを使います。利用アカウントの可用性は実接続で確認し、未対応時に別モデルへ黙って変更しません。面接中の委譲はResponses方式とし、ツール呼び出し・Web検索・追加ファイル取得を無効にします。

GPT-Liveの文字起こしには発言完了イベントがないため、受信断片を原文として順序保存し、表示用の発言区切りを話者・時刻・接続世代から決めます。再生完了を推測せず、ブラウザからの再生位置の確認を別に記録します。聞けなかった範囲は未確認として扱います。アプリの指示と材料を分離し、材料内の命令を実行しない指示を音声・分析・評価のすべてへ適用します。

一時停止は最大5分、切断後の再接続待ちは最大1分です。停止中は上流接続を閉じ、音声送受信・再生・時間計測を止めます。別タブは読み取り表示とし、明示的に引き継ぐと接続世代を更新して古いタブの音声・操作を拒否します。DO再起動後もD1から状態を復旧します。

再開時は同じ面接IDで新しい上流接続を開始します。固定材料・背景・直前の会話を含む文脈が上流の履歴上限に収まる場合に再開し、収められない場合は黙って切り捨てず終了・評価へ進めます。再開用の文脈は評価の原文へ上書きしません。

終了では送受信を止め、上流終了イベントを待ちながら残る文字起こしの保存を直列に完了します。15秒以内に上流終了を確認できなければ欠落の可能性を記録します。固定した会話とジョブ・outboxの永続化後に終了受付を返します。通信断の再送でも同じ面接に二重の初回評価を作りません。

## 評価と障害処理

既存の実行権、本人全体の同時1件制限、120秒のAI期限、180秒の試行期限、再試行・DLQ・定期回復を正式評価でも使います。診断用の評価処理は別入口に残し、制御ロジックを複製しません。

結果形式だけでなく、軸が重複なく5つあること、点数と未確認・対象外の整合、引用が保存済み発言に実在することを検証します。材料に書かれた実績を面接中の発言として引用しません。回答がない場合はAI採点を行わず、回答なしの結果として保存します。手動再実行では新しいジョブIDを発行し、モデル・指示を含む固定入力を引き継ぎます。

認証・設定不足は再試行せず、レート制限・一時障害は既存の再試行規則に従います。結果保存だけの再試行ではAIを呼び直しません。生の外部エラー、秘密値、音声、材料・会話全文をログへ出しません。

## ローカル実行と利用量

[ADR 0009](../../adr/0009-explicit-environments.md)の環境分離を維持します。開発はlocalhostの本人用入口に限定し、Host・Origin・操作トークンを検証して別サイトからの有料API実行を防ぎます。自動テストでは外部AIを呼ばず、独立したtest環境と架空データを使います。本番入口は認可未設定のまま公開できない状態を保ちます。

秘密値は1Passwordから起動プロセスへ注入し、ランタイムへメモリ内だけで引き渡します。環境ファイル、生成設定、ビルド出力、ログへ保存しません。現在のランタイム生成処理は設定をファイル出力するため、秘密値をそのvarsへ加える実装は禁止します。対応する注入経路の実動作確認を実AI接続前の検査に含めます。

固定版のコードを静的に確認したところ、ローカル起動は親プロセスの環境を引き継ぎ、Cloudflare Viteプラグインの環境読込処理もプロセス環境を取り込みます。ただし、これだけで各Workerへの秘密値の供給や、ビルド成果物への非混入を保証できません。実装時は起動に必要な環境と明示したAI設定だけを渡し、架空の検査値でWeb・Interview・Evaluationへの到達範囲と生成ファイルへの非混入を確認してから実キーを使います。参照箇所は`tools/local-integration/src/runtime.ts`の`runtimeEnvironment`と、固定版Cloudflare Viteプラグイン2.0.0-beta.v.9の`loadEnv`です。

利用量の初期案は、材料32KiB、分析10回／日、音声60分／日・1面接20分、評価の新規実行10回／日です。日付はAsia/Tokyoです。分析・評価はD1で実行枠を原子的に予約します。音声は本人につき一つの面接DOが開始を直列化し、日次残時間から終了期限を決めます。面接中の区間を状態更新と一体で記録し、開始準備・再接続待ち・一時停止は利用時間に含めません。評価の自動再試行は新規実行枠と分けて最大4試行に制限します。金額の厳密な上限ではないことを画面に示します。モデル設定とともに変更可能な非秘密設定として集約します。

## 検証と完了条件

実装はRed/Green TDDで進めます。テストを一つ追加してルートの`pnpm test`で期待する失敗を確認し、最小実装後に同じコマンドで成功を確認します。通常検査は`pnpm check`、Worker間接続・配送・回復は`pnpm test:integration:pr`と`pnpm test:realtime`を使い、追加検査の所属定義も更新します。

1. 送信確認前にAIへ送らない。上限超過・不正形式・引用不一致を拒否する。
2. 本物のローカルD1・DO・Queueを通り、面接終了から非同期評価・結果表示まで到達する。外部AIスタブ検査と実AI検査を別の証拠として残す。
3. マイク拒否、接続失敗、保存失敗、一時停止、切断、タブ引き継ぎ、二重終了、ランタイム停止後の回復を確認する。
4. 実行権の競合・再試行・手動再実行・削除後の遅延通知が既存規則を守る。
5. ブラウザで材料選択・テーマ選択・音声入出力・現在の質問・評価根拠への移動を確認する。実マイクによる日本語対話と15分程度の接続は本人の操作を含めて確認する。
6. 指定の経験Markdownを使い、実音声AIからの文字起こしを保存し、実AI評価が完了して表示される。モデル、実行日時、検証範囲、欠落・費用の観測可能な範囲を記録する。
7. 秘密値がディスク・ログ・ブラウザへ出ず、通常テストが有料APIを呼ばないことを検査する。

実APIの資格情報・モデル権限や本人のマイク操作が未確認なら、実装と自動検査が通っても全体を完了としません。

## 実装前に利用者が確認する事項

既存構成を使う今回の範囲、利用量上限の初期案、実AI検証でこのMarkdownを送ることを確認します。秘密値の登録が必要な場合は1Passwordの正規UIを使い、チャットで値を求めません。モデルと環境の既存設定を非秘密情報だけで確認してから、未決のものだけを相談します。

## 公式資料の確認

2026年11月6日にOpenAI Docsで以下を取得しました。APIの接続形式の根拠であり、利用アカウントでの成功を示すものではありません。

- [GPT-Live WebSocket](https://developers.openai.com/api/docs/guides/voice-websockets?api=live)：認証、開始確認、音声形式、終了処理。
- [セッション管理](https://developers.openai.com/api/docs/guides/live-conversations)：文字起こし、履歴からの開始、録音保存、音声再生との区別。
- [推論の委譲](https://developers.openai.com/api/docs/guides/live-delegation)：Responses方式とツール無効化。
- [構造化出力](https://developers.openai.com/api/docs/guides/structured-outputs)：生成Schemaの制約と結果の検証。

- [CloudflareのWebSocket接続](https://developers.cloudflare.com/workers/examples/websockets/)：WorkerからUpgradeヘッダー付きfetchで接続し、返されたWebSocketをacceptする方式を実装に使用します。認証ヘッダーはサーバー内だけで扱います。
