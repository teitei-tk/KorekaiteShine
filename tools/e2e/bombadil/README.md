# 材料確認と履歴の画面探索

Bombadilで`/practice`の操作順を変え、材料確認と履歴・削除の不整合を探す。既存の[音声E2E](../README.md)と固定の回帰テストに追加する補助検査であり、音声開始・評価再実行・実AIは対象にしない。導入範囲と検証の進捗は[実装計画](../../../docs/superpowers/plans/2026-11-17-bombadil.md)、採用版の根拠は[適合性検証](../../../docs/research/bombadil.md)を参照する。

## 準備と実行

リポジトリルートで、固定版の依存・生成契約・ブラウザを用意する。

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm --filter @korekaite/api-contracts generate
pnpm --filter @korekaite/e2e exec playwright install chromium
```

既存のChromeを使う場合は、`E2E_CHROME_PATH`に実行ファイルの絶対パスを設定する。指定がなければ固定版PlaywrightのChromiumを使い、別のブラウザへ自動で切り替えない。実際に使った実行ファイルの版とハッシュは記録へ保存する。

```sh
pnpm test:exploration --target preparation
pnpm test:exploration --target history --seconds 300
```

探索時間は60〜600秒、既定は120秒。起動・停止を含む外側の予算は指定秒数＋180秒とする。Ctrl-CやSIGTERMでも後処理を行う。通常の`pnpm test`は補助コードの単体検査だけを実行し、ランダム探索を起動しない。

対象チェックアウトのPR用ランタイムを起動し、専用のtest環境へ架空の終了済み面接2件を投入する。各記録は異なるテーマ・発言・評価を持つ。任意URLやliveプロファイルは受け付けず、`E2E_APP_ROOT`で別のチェックアウトへ向けることもできない。開発DBのリセットや実行途中のデータ補充は行わない。

## 結果と記録

標準出力へ結果のJSONを出し、既定では`.local/bombadil/実行ID/`へ保存する。`--output`で新しい保存先を指定できるが、既存ディレクトリは上書きしない。

| 状態                   | 終了コード | 意味                                                         |
| ---------------------- | ---------- | ------------------------------------------------------------ |
| `passed`               | 0          | 有効な操作記録があり、必要な状態へ到達して、違反なく終了した |
| `violated`             | 2          | 操作記録とエンジンの終了結果が性質違反を示した               |
| `incomplete`           | 3          | 操作ゼロ、必須状態の未到達、利用者の中断、外側の期限超過など |
| `infrastructure_error` | 1          | 起動・停止・記録解析の失敗、再現条件の不一致など             |

必要な状態へ到達しなかった場合も失敗として扱い、探索時間を増やす自動再試行はしない。`passed`は全操作順の正しさを証明するものではない。

準備画面では正常分析、確認後の編集、未確認時の送信禁止、画面を開き直した後の遅延分析応答の分離を必須条件とする。連打の生成では入力イベント間の画面反映を挟み、応答を保留したまま2回目の入力を試す。

記録の構成：

- `result.json`：状態、操作数、到達条件、保存先。
- `metadata.json`：実行ID、対象、時刻、終了理由、Git SHA、作業ツリーの内容・仕様・fixtureのハッシュ、Bombadilとブラウザの版・ハッシュ。
- `fixtures.json`：初期データのseed、ID、固定時刻、架空のテーマ・発言・評価。
- `bombadil/`：操作記録`trace.jsonl`、画面画像、エンジンのログ。

準備画面の観測では同じ本文を材料辞書へ一度だけ保存し、編集や要求から参照番号で対応付ける。性質の判定時は元の本文へ復元する。履歴では削除した各IDの再取得確認が必要で、以前に到達条件を満たしていても未確認が残る実行は`incomplete`とする。

画面と入力内容が記録されるため、探索には用意した架空データを使う。環境変数全体や実AIの資格情報は保存・継承しない。

## Inspectと再現

以下の`実行ID`は確認したい記録のディレクトリ名へ置き換える。Inspectはブラウザを開き、操作記録と画面を確認する。

```sh
pnpm --filter @korekaite/e2e exec bombadil browser inspect ../../.local/bombadil/実行ID/bombadil
```

再現は保存済みのseed・ID・時刻を、新しい隔離環境へ復元して行う。元の環境を再利用せず、元の記録も変更しない。例は履歴を300秒探索した記録の再現。

```sh
pnpm test:exploration:reproduce --target history --seconds 300 --reproduce .local/bombadil/実行ID
```

再現には元の対象と十分な外側の時間予算を指定する。再現モードではBombadilの探索時間指定を使わず、ランナー側の期限を適用する。ソース・未コミット変更・仕様・fixture・ブラウザ・Bombadilが記録時と異なる場合は、起動前に`reproduction_mismatch`として拒否する。保存済みの記録を編集して照合を回避しない。同じ条件でも応答速度などによって再現に失敗する場合があり、性質違反とは区別して扱う。

## 不具合を固定テストへ移す

1. `result.json`と`metadata.json`で、性質違反・未到達・基盤エラーを区別する。
2. Inspectで直前の操作、要求・応答、表示を照合し、同じ初期状態から再現を試す。
3. 最小の操作順へ絞り、既存VitestまたはCucumberへ固定の回帰ケースを追加する。表示とAPIの処理結果を混同しない。
4. そのテストのRedを確認してから修正し、通常の検査を通す。遅延応答が必要なら固定した保留・解放で再現し、乱数だけに依存させない。

探索の仕様を弱めたり、必須到達条件を削ったりして失敗を隠さない。Queue配送・実行権・音声停止・実AIの品質は、それぞれ既存の専用検査で確認する。

## 手動CI

GitHub Actionsの`Bombadil exploration`から手動実行する。準備画面と履歴を別ジョブで各300秒探索し、各ジョブの上限は20分とする。PRごとの必須検査や定期実行には追加していない。

既存CIと同じ固定Playwrightコンテナ、Node・pnpm、Takumi Guardと依存保護設定を使う。ブラウザとPlaywrightの版が一致しない場合は探索前に停止する。LinuxのrootコンテナではChromeに`--no-sandbox`を渡すため、隔離したジョブ内の架空データとローカルアプリだけを対象にする。`violated`・`incomplete`・`infrastructure_error`はそれぞれ非ゼロ終了となり、ログの結果JSONで区別する。記録が欠落・解析不能の場合も成功にはしない。

成功・失敗にかかわらず`.local/bombadil/`を成果物として7日間保存する。期限内にダウンロードし、Inspectや再現に使う。ローカル再現には記録時と同じソース・初期データ・実行ファイルが必要で、Linuxの記録を異なるmacOSブラウザへそのまま渡して再現済みとは扱わない。

このWorkflowはmainへ取り込む前はGitHub上で起動できない場合がある。ローカルの実行結果とGitHub runnerでの結果は区別し、実際の実行履歴がない段階では手動CIを検証済みとしない。
