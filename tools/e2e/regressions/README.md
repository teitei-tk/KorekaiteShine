# 音声面接の修正前の挙動を再現する

5つのシナリオを、原因ごとに修正を戻したアプリで実行する。一度に適用するパッチは1つとし、各回で修正後のソースから新しい一時コピーを作る。契約・Worker・UIはコピーしたソースからビルドする。

## 復元元

音声面接の実装は元の作業ツリーで未コミットだった。2026年11月6日から8日の開発チャット（ID `01a1b0c2-3f61-7db1-a452-ad97978bffd4`）に記録されたソース変更と、修正後の実装を照合した。表の時刻はUTC。

| パッチ                | 対応するシナリオ                   | 復元した変更と観測点                                                                                                                                                                                                     |
| --------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `audio-event`         | 最初の音声応答                     | 11月8日04時47分のTypeSpec変更を逆に適用し、出力音声の `event_id` を再び必須にする。IDを持たない音声断片が検証で拒否され、ブラウザに音声が届かない。                                                                      |
| `failed-reservation`  | 接続に3回失敗                      | 11月6日16時12分の予約・精算SQLと16時13分の開始処理を現行のセッションに組み込む。上流接続前に残り面接時間と45秒を予約し、正常終了時だけ精算する旧条件を復元した。開始に失敗した世代の予約額が当日の残り時間から引かれる。 |
| `active-usage`        | 一時停止・再接続待ちを除く利用時間 | 同じ予約・精算処理を復元する。11月8日04時48分の区間集計追加より前と同じく、上流の終了通知の秒数を使用する。現在の残り時間APIを通して旧集計を検査できるよう、そのSQLを予約額合計だけに変更した。                          |
| `manual-reconnect`    | 発話途中で切断後に手動再接続       | 11月8日05時18分の修正前のクリック処理を復元する。再接続時に `resume: false` を設定し、同じタブの面接再開操作が失われる。                                                                                                 |
| `restart-credentials` | サーバー再起動後に同じタブで復帰   | 同時刻に追加されたWebSocket再接続前のセッション再取得を取り除く。固定URLのままサーバーが認証情報を更新すると、以前のCookieでの接続が拒否される。                                                                         |

追加の `upgrade` は11月8日04時34分の変更を逆に適用し、Workerの上流WebSocket接続を `redirect: 'error'` に戻す。最初のシナリオで使う `audio-event` と独立している。上流の接続方式に依存するため、音声イベント検証の再現には併用しない。

利用枠の2パッチは、現在のAPI・スキーマ・開始失敗後の再試行機能から旧計量処理を呼べるようにした再構成である。その他のパッチも原因に関係する箇所だけを戻す。過去のビルド全体を保存したものではない。

## 再現手順

対象のGit作業ツリーで依存をインストールし、API契約を生成しておく。以下はE2Eのあるリポジトリのルートから実行する。`app_source` には修正後の音声面接アプリがあるGit作業ツリーのルートを指定する。

```sh
fixed=$(node tools/e2e/regressions/snapshot.mjs "$app_source")
red=$(node tools/e2e/regressions/snapshot.mjs "$app_source" audio-event)
E2E_APP_ROOT="$red" node tools/e2e/run.mjs pr '最初の音声応答'
E2E_APP_ROOT="$fixed" node tools/e2e/run.mjs pr '最初の音声応答'
```

スクリプトはGitの追跡対象と除外されていない未追跡ソースを一時ディレクトリにコピーし、認証用の設定ファイルを除外する。標準出力はコピーの場所、標準エラーはパッチ適用前のソースのSHA-256と生成処理のログに使う。両方の実行でSHA-256が一致することを確認する。依存ライブラリは対象ツリーのインストールを使用し、ワークスペース内パッケージはコピー内で解決する。

原因名を指定すると、コピー上で差分の適用可否を確認してから適用する。`audio-event` は変更したTypeSpecからイベントの型とvalidatorも再生成する。他の原因では表のパッチ名と該当するシナリオ名を指定する。作成した一時コピーは、検証記録を確認した後で削除する。
